# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

An Electron + plain-Node desktop tool that repairs GLB (glTF 2.0 binary) models that open fine in 3D viewers but fail to render in Cesium, then previews the result in a bundled local Cesium. The core is a **hand-written GLB binary parser/repacker with no third-party glTF libraries** — all format handling lives in the code, not in a dependency.

The app is split into two layers:

- `src/repair.js` — the repair engine. Pure Node (CommonJS), no Electron or npm runtime deps, so it runs and tests under plain `node`.
- `src/ive.js` — the IVE→GLB converter: drives the native `ive2glb` helper and assembles a self-contained GLB in Node. Also pure Node (uses only `jpeg-js`/`pngjs` plus `repair.js`'s `writeGlb`/`align4`/矩阵工具). It welds vertices, applies the Z-up→Y-up axis conversion and grounds/centers the model; conversion options are documented in its JSDoc.
- `src/convert.js` — the FBX/OBJ→GLB converter (REQ-007/ADR-008): runs **assimpjs (assimp compiled to WASM, MIT)** in-process — no external executable, no per-platform binary — then does the three things assimp does not: welds the triangle soup by reusing `src/ive.js`'s exported `weldVertices` (generalised to decode integer attribute types too, so skinned FBX primitives weld), embeds external textures via `repair.js`'s `resolveExternalImage` (assimp writes OBJ textures as `images[].uri` even for relative paths, and a data-URL preview cannot read those), and replaces unresolvable textures with a 1×1 placeholder carrying a `missing:<uri>` name plus a warning (never silently drops a texture, never leaves an unreadable `uri`). Never throws: returns `{ status, bytes, warnings, stats }`.
- `src/inspect.js` — read-only model 体检 (inspection) report: file bytes, node/mesh/primitive counts, vertices & triangles, texture specs (dims, NPOT, 1×1 placeholders, sampled-or-not), materials/samplers, `bounds.world` vs `bounds.accessorUnion` with a deviation factor, bounds center, conservative up-axis guess, scale hints, and a Chinese issue list. Also usable as a CLI: `node src/inspect.js <file.glb>`.
- `src/transform.js` — world-bounds and matrix helpers (`worldBounds`, `accessorUnionBounds`, `deviationFactor`). The node-chain walk is **shared** by the GLB inspection path (local boxes from accessor `min`/`max`) and the IVE conversion path (local boxes measured from raw float ranges) — `src/ive.js` delegates to it.
- `src/report-format.js` — turns an `inspect.js` report into the Chinese rows the 体检 panel shows (`formatBox`/`formatCenter`/`deviationText`/`deviationLevel`/`factRows`/`issueCounts`/`sortIssues`). Pure functions, no DOM/Electron; a partial or malformed report must never throw or render `undefined` (BR-025). Loaded in the renderer as a plain `<script>` that also exposes `window.reportFormat`, and required directly by `node --test`.
- `src/preview-transform.js` — the preview-only direction/scale/up-axis correction: `previewMatrix({ yawDeg, scale, axis })` returns the column-major 16-element Cesium `modelMatrix` (uniform scale × rotation about Y, **no translation**), where `axis: 'z'` additionally composes `Rx(−90°)` innermost (the manual Z-up→Y-up tri-state ADR-002 requires; `auto`/`y` add nothing, and inference never applies it automatically). `clampPreview` normalizes/validates the input, `describePreview` renders the Chinese summary and `axisOptions()` feeds the `<select>`. Also a plain `<script>` exposing `window.previewTransform`. Preview corrections are **never written back** to any file (BR-024/ADR-004).
- `native/ive2glb/` — a small C++20 helper that reads IVE with OpenSceneGraph and dumps `scene.json` + `data.bin`; build and vendoring are covered by `npm run build:ive2glb` and `native/ive2glb/README.md`.
- `src/main.js` + `src/preload.js` + `src/renderer.js`/`index.html` — the standard Electron main/preload/renderer shell over IPC.

**All UI strings, log lines, and thrown error messages are Chinese (zh-CN);** keep new user-facing strings Chinese for consistency. The design doc (`docs/001-code-design.md`) and issue analysis (`docs/cesium-glb-load-issues.md`) are Chinese too.

## Commands

- `npm install` — installs the Electron dev toolchain.
- `npm run build:ive2glb` — builds `native/ive2glb` and vendors a **self-contained** helper into `vendor/ive2glb/darwin-<arch>/` (executable + `lib/*.dylib` + `osgPlugins/`), rewriting deps to `@rpath` and ad-hoc re-signing. macOS only; the Windows steps are in `native/ive2glb/README.md`.
- `npm run dev` / `npm start` — runs `ensure:cesium` then launches Electron (app entry is `src/main.js`).
- `npm run ensure:cesium` — downloads the Cesium 1.128 release zip and unpacks it to `vendor/cesium/1.128/Build/Cesium/` only if `Cesium.js` + `Widgets/widgets.css` are missing. Needed before `dev`/`start` because `index.html` loads Cesium from that exact relative path as a plain global `<script>` (no bundler).
- `npm run lint` — `node --check` (syntax check only) over **every** `src/*.js` via a `for` loop, so a newly added module is covered automatically (an explicit file list silently skipped `src/ive.js` once). Not a style linter.
- `npm test` — Node's built-in test runner, scoped to `node --test "test/*.test.js"`. **The glob is load-bearing**: bare `node --test` treats *every* file under a `test/` directory as a test, so it picked up the manual harness `test/ui-smoke.cjs` and hung the suite for 60s. `package.json` declares `engines.node >= 21` because the glob expansion is Node's own feature (added in 21) — do not go back to an explicit file list, which silently stops covering new test files (the `npm run lint` list once skipped `src/ive.js` exactly that way). The suite is committed, the sample models are not: on a fresh checkout **14 tests skip and 0 fail (measured `pass 92 / skipped 14`)** — 6 in `repair.test.js` needing `refs/models/*`, 5 in `ive.test.js` needing `o-model/*.ive`, 3 in `inspect.test.js` needing the sample corpus (`运输车.glb`, the corpus sweep, `model/蹲姿.glb`). Each prints the missing files and the recovery command after the `#`. `test/convert.test.js` (REQ-007) gates six of its nine cases on `o-model/蹲姿.fbx` / `蹲姿.obj` / `蹲姿.glb` + `model/蹲姿.glb` via its own `convertSkipReason()`; locally the suite measured `115 tests / 111 pass / 0 fail / 4 skip`. All these files use the same `fixtureSkipReason()` pattern — and **each fixture group must gate only on its own files**: `crouchSkipReason()` used to call `fixtureSkipReason()` (which queries `person-move.ive`), so the 蹲姿 golden and welding cases were skipped even when `蹲姿.ive` was right there. Keep the pattern, because a committed suite that hard-fails on a clean clone is worse than one that skips.
- Run one test file: `node --test test/repair.test.js`. Filter by name: `node --test --test-name-pattern='external PNG'`.
- `node test/ui-smoke.cjs <model> --port 9333` — the **manual** UI wiring smoke test (not part of `npm test`): start the app as `npx electron . --remote-debugging-port=9333` in another terminal, then run it. It drives the real renderer over the DevTools Protocol in small per-step `Runtime.evaluate` calls (a single big awaited evaluation hangs against a freshly started instance), asserting the 体检 panel renders real values, the preview sliders/up-axis only touch `modelMatrix`, dragging logs nothing while `change` logs the final matrix, and the input file's `shasum` is unchanged. Exit code 0 = all checks pass. It calls `Page.bringToFront` first, but **macOS occlusion is not the same as tab activation** — while the window is hidden the page would be throttled, `requestAnimationFrame` would never run, Cesium would render zero frames and `validateModel` would never settle. The app therefore sets `backgroundThrottling: false` (BR-026) and `waitForModelReady` has a timeout that reports 「已创建模型，但当前未渲染…」 instead of success, so a throttled window can never masquerade as a green smoke run.
- `npm run dist:win` — `electron-builder` Windows x64 NSIS + portable into `dist/`.

**Transcoding is self-contained — images *and* models:** non-PNG images (JPEG) are converted to PNG in-process via the `jpeg-js` + `pngjs` production dependencies (`encodePng` in `src/repair.js`); FBX/OBJ are converted in-process by `assimpjs` (WASM). Do NOT shell out to an external binary like `ffmpeg` (or a native `assimp`/`FBX2glTF`), and do NOT add a per-platform binary — packaged end-user apps have none, which produced `spawnSync ffmpeg ENOENT`; the IVE helper is the cautionary tale, since it only ever shipped for darwin. `jpeg-js`/`pngjs`/`assimpjs` must stay under `dependencies` (not `devDependencies`) or electron-builder won't package them into the asar; the assimpjs wasm additionally needs `asarUnpack` (`node_modules/assimpjs/dist/**`) because it is read from disk by path.

Several directories the code depends on are **gitignored and present only locally**: `vendor/cesium/` (downloaded by `ensure:cesium`), `refs/models/*.glb` (fixtures that `npm test` copies), and `model/` (scratch sample GLBs). After a fresh clone, `npm run dev` regenerates `vendor/cesium/`; tests that need fixtures skip with a clear reason (see the `npm test` bullet) instead of failing.

**What goes into git** (`.gitignore` policy): source in, artifacts out. `native/ive2glb/**` (C++ sources, `CMakeLists.txt`, README) and `scripts/build-ive2glb.sh` are source and must be committed — the latter is the only way to reproduce the vendored helper. `native/ive2glb/build/` (CMake output) is ignored. `vendor/ive2glb/<platform>-<arch>/` is a **vendored distribution artifact that `package.json`'s `asarUnpack` + `files` require at packaging time**; it is deliberately *not* ignored, because the build script is macOS-only and there is no CI to produce it. `test/` is tracked source, and `scripts/ensure-cesium.js` is a product script. Keep packaging ignores root-anchored (`/dist/`, `/release/`, `/out/`) — never add a blanket `*.exe` / `*.zip`, or a future `vendor/ive2glb/win32-x64/ive2glb.exe` would be silently dropped from the installer. The anchor is load-bearing: an unanchored `release/` matches a directory of that name at any depth, and it silently swallowed `.ai/skills/release/`, leaving `.ai/platform-lock.json` referencing three files that never made it into a commit. The workflow engine and entry points (`.ai/`, `dsh/`, `scripts/*.mjs`) are **tracked**, by `chore(platform)` commits: a fresh clone and any worktree must be able to run the Tenon flow, and `platform-doctor`'s `tracked` / `cloneable` checks fail when they are missing. `scripts/ensure-cesium.js` and `scripts/build-ive2glb.sh` stay tracked alongside them. `docs/` 的入库范围由 `.gitignore` 逐条放行，`git ls-files docs/` 应恰好是 **13 份**：三份项目设计文档（`001-code-design.md`、`002-requirements.md`、`cesium-glb-load-issues.md`）加上跑通 Tenon 流程所必需的十份平台文档（`requirements/REQUIREMENTS.md`、`requirements/TASKS.md`、`PROJECT_MEMORY.md`、`approvals/APPROVALS.md`、`testing/TEST_PLAN.md`、`testing/PERF_BUDGET.md`、`release/RELEASE_CHECKLIST.md`、`release/MERGE_REQUEST.md`（`task-flow` 生成的派生物，但同样入库）、`design/ADR.md`、`api/openapi.json`）——REQ-001/REQ-002 明确要求台账与两份基线入库，**别再把这些当模板忽略掉**；其中 `testing/PERF_BUDGET.md`、`release/MERGE_REQUEST.md`、`api/openapi.json` 是随 `chore(platform): declare docs/coding-standard not applicable and track the remaining seeds` 按 `.ai/platform-lock.json` 补齐的。唯一仍忽略的是与本项目技术栈无关的平台模板 `coding-standard/`，它已在 `.ai/platform-lock.json` 的 `meta.excluded` 里声明不适用——这才是「确实用不上」的正规做法，`platform-upgrade` 与 `platform-doctor` 都会跳过它。`.gitignore` 里必须写成 `docs/*` 加逐目录的 `!` 否定（父目录也要显式放行）——一旦整个 `docs/` 或某个子目录被排除，后面的 `!` 规则无法把文件捞回来。

## Repair pipeline (`src/repair.js`)

`repairGlbFile(inputPath, outputPath)` reads a GLB, mutates the parsed JSON + BIN in place, and writes a new file. One call repairs one file and **never throws** — it returns a `report` object with `status: 'success' | 'error'` and a Chinese `error` message on failure, so `repairMany` (batch/directory scan) keeps going past bad files. A repaired file keeps the original's basename in the chosen output dir (BR-001).

Steps run in this order; each has byte-layout consequences:

1. **`bakeSkinnedMeshes`** — bakes skinned primitives (mesh nodes with `skin`; `JOINTS_0`/`WEIGHTS_0` attrs) to static ones. It does its own node/scene walk (`computeNodeGlobalMatrices`), TRS→matrix and 4×4 inverse math, and per-vertex skinning with up to 4 influences using `inverseBindMatrices`. Rewrites POSITION/NORMAL accessor bytes and **recomputes `accessor.min`/`max`** (Cesium reads these for culling/framing — stale bounds are a root cause of "loads but invisible"). Strips `JOINTS_0`/`WEIGHTS_0`, and if any mesh was baked, deletes `skins` and `animations`.

   **Pose freezing:** by default it bakes to the **bind pose** — so an animated character whose action (e.g. a crouch) lives only in its animation clip would collapse to the standing bind pose. Pass `options.poseTime` (a number of seconds, or `'start'`/`'end'` of animation index `options.animationIndex`, default 0) to first sample the glTF animation (LINEAR slerp/lerp + STEP are handled via `computePosedLocalMatrices`/`sampleAnimationChannel`) and bake in that posed frame instead. The app exposes this as the "烘焙为动画起始姿势" checkbox (`freezePose` → `poseTime: 'start'`). A file with no animation is unaffected (resolves to `null`).
2. **Image normalization** — for each `image`, either read its `bufferView` bytes out of the BIN, or resolve an external `uri` via `resolveExternalImage`. PNGs are kept as-is; JPEG bytes are converted to PNG in memory by `encodePng` (`jpeg-js` decode → `pngjs` encode). Any other image format throws a per-file error telling the user to supply PNG/JPEG. Every image ends up `mimeType: 'image/png'`. `resolveExternalImage` handles data URIs, absolute paths (incl. Windows `C:\...`), relative paths, and recursive by-name search next to the GLB (catches `.fbm` folders). A missing external image throws a recovery message telling the user to place the file / its `.fbm` dir beside the GLB.
3. **`stripSpecularExtensions`** — removes `KHR_materials_specular` from `extensionsUsed`, `extensionsRequired`, and per-material `extensions` (empty arrays/objects are deleted, not left as `[]`/`{}`).
4. **`fillMissingTexCoords`** — for a primitive whose material samples a texture (any of `baseColorTexture` / `metallicRoughnessTexture` / `normalTexture` / `occlusionTexture` / `emissiveTexture` / a `*Texture` in an extension) at `texCoord: n` but which has no `TEXCOORD_n` attribute, appends a zero-filled float32 `VEC2` accessor sized to the primitive's `POSITION.count`. Such primitives otherwise make Cesium generate a fragment shader referencing an undeclared varying — the compile failure stops rendering for the **whole scene**, not just that model.
5. **`mergePrimitivesByMaterial`** — the Cesium scalability fix. Cesium 1.128's model load time grows super-linearly with primitive count (measured: 6 prims 0.6s, 50 prims 9.3s, 100+ never finishes). When a file has more than `options.mergePrimitiveThreshold` primitives (default 100), primitives sharing a material and an attribute format are merged into one, baking each mesh node's **world matrix** into POSITION (via `transformPoint`) and NORMAL (via `transposeMatrix(invertMatrix(...))` + `transformVector`). Zero-filled `TEXCOORD_n` is synthesized for members lacking it, so UV presence never splits a group. **Triangle winding is reversed per primitive when `determinant3(world) < 0`** — many of these models use mirrored nodes and every material is `doubleSided`, so skipping this inverts lighting without changing the silhouette. Merged indices are always `uint32`. New streams go into **appended** bufferViews (never reuse a source view: an accessor can be shared across material groups). Consumed meshes get `primitives: []` (not just the surviving one) because `getPositionBounds` in `main.js` unions every mesh's POSITION `min`/`max` with no node-transform awareness. Scene restructuring appends an identity root node holding the merged mesh, so no existing index needs remapping. It **skips** (whole file, no-op) on Draco/meshopt, morph targets, animations, skinned bakes, instanced meshes, non-TRIANGLES modes, non-float32 attributes, sparse accessors, interleaved views, multi-buffer files, or nodes unreachable from the default scene.
6. **`rebuildBinary`** — the repack pass. BufferView bytes that changed are supplied as a `Map<bufferViewIndex, Buffer>` (from steps 1–2, 4–5). It sorts views by original `byteOffset`, re-emits gaps as-is, **keeps every 4-byte alignment**, and rewrites each `bufferView.byteOffset`/`byteLength` and `buffers[0].byteLength`.
7. **`appendBufferViewToBinary`** — external or newly-converted external images (now PNG) are appended as new `bufferView`s; their `uri` is deleted and `mimeType` set to `image/png`. Steps 4–5 use the same helper to append merged/UV bytes.

Appending steps thread a `workingBin` (`let workingBin = bin`) and register their new bytes in `replacements`, because `rebuildBinary` copies any view absent from the map straight out of the bin it is handed. `mergePrimitivesByMaterial` reads and appends against the same `workingBin`, so it sees the UV accessors step 4 just added.

Format invariants that are easy to break (there are helper tests but no golden-binary snapshot tests):

- GLB container: 12-byte header (`glTF`, version 2), JSON chunk padded with spaces `0x20` to a 4-byte boundary, BIN chunk padded to 4; all lengths little-endian. `readGlb`/`createGlbBuffer`/`writeGlb` encode this.
- Only **non-interleaved** bufferViews are supported — a view with `byteStride` throws (`readAccessorData`).
- Accessor `min`/`max` must stay in sync whenever you rewrite POSITION data.
- `align4`, matrix helpers (`identityMatrix`, `multiplyMatrix`, `invertMatrix`, `transformPoint`, `transformVector`, `getNodeLocalMatrix`, `getTypedArrayConstructor`, `readAccessorData`) are exported/testable primitives used by the bake.

The batch entry points `collectGlbEntries` (returns `{ inputPath, relativePath }`, preserving nested structure under a directory root) and `collectGlbFiles` mirror the earlier standalone scripts under `refs/scripts/` — the `refs/` versions are the pre-productization originals of this logic.

## IVE input pipeline (`src/ive.js` + `native/ive2glb`)

IVE is OpenSceneGraph's private serialized scene format. **There is no JS/WASM IVE parser** (npm only has `.osgb/.osgt` serializer libraries), so reading IVE requires native OSG code. The design keeps that native part thin and leaves all format authoring in Node:

```
input.ive ──▶ ive2glb (C++/OSG) ──▶ <tmp>/scene.json + data.bin
                                        │
                      src/ive.js (Node) ─┴─▶ self-contained GLB ──▶ repairMany ──▶ Cesium preview
```

- **`native/ive2glb/src/main.cpp`** links only `libosg`/`libosgDB` (no Qt, Assimp, `osgViewer`, `osgGA`, or GL context). It walks the scene graph with its own recursive `Builder::addNode`, converts every vertex attribute to float32 and every index to uint32, expands strips/fans/quads/polygons into triangles, and writes `scene.json` (nodes, materials, image metadata, byte ranges) plus `data.bin`. It prints one line of JSON on stdout (`{"status":...,"images":...,"binBytes":...}`) and exits non-zero on failure. `registerLocalPluginPath()` **inserts** the bundled `osgPlugins/` at the **front** of `osgDB::Registry`'s library path list — `push_back` is not enough, because OSG's compiled-in plugin path (the dev machine's Homebrew install) wins and the vendored libs never load.
- **`src/ive.js`** runs the helper via `spawnSync` into a temp dir, then assembles the GLB with `writeGlb`/`align4` from `repair.js`: bufferViews for attributes (`ARRAY_BUFFER`), indices (`ELEMENT_ARRAY_BUFFER`) and images (no `target`), plus POSITION `min`/`max` computed from the dumped floats (Cesium needs them for framing). Materials map `Material.diffuse` → `baseColorFactor`, `Texture2D` unit 0 → `baseColorTexture`, `roughnessFactor` from `sqrt(2/(shininess+2))`, and `doubleSided: material.cullFace === 'absent'` (an absent `CullFace` means GL culling was off).
- **Pixel orientation is the trap.** `osg::Image` stores rows bottom-up (`origin: BOTTOM_LEFT`, OpenGL convention) while PNG/JPEG are top-down. `readImagePixels()` reads rows in reverse when `origin !== 'TOP_LEFT'`. Verified against the reference `.fbm` JPEG: correct orientation gives a row-0 MAE of ~0.5; skipping the flip jumps to ~35.
- **Textures are always embedded** (`bufferView` + `mimeType`, no external `uri`). `keepJpeg` (default on) selects JPEG at `jpegQuality` 90; images with an alpha channel force PNG because JPEG would drop transparency. Non-power-of-two images fall back to `CLAMP_TO_EDGE` + `LINEAR` (mipmapped `REPEAT` is invalid for NPOT). Note this `keepJpeg` belongs to `src/ive.js` only — the repair step downstream re-encodes every JPEG to PNG (BR-002), so a converted GLB ends up with PNG textures unless it is previewed as-is.
- **Empty subtrees are pruned** by default (`pruneMeshlessSubtrees`): IVE files typically carry a whole `mixamorig:*` bone hierarchy that renders nothing (72 nodes → 7 for `person-move.ive`). Pass `pruneMeshlessNodes: false` to keep them.
- **IVE is Z-up, glTF is Y-up** (BR-013/014/015). Without the `-90°` about X rotation baked in, models arrive in Cesium lying down (蹲姿: `0.538 × 1.056 × 1.171` instead of the reference's `0.538 × 1.364 × 1.056` — Y/Z swapped). `createAxisConversion` computes the **world AABB by walking the node chain accumulating matrices** (never from accessor min/max — those ignore node transforms and were off by up to 90,000×), then rotates it, then sets `T = (-centerX, -minY, -centerZ)` so the model lands grounded and horizontally centered; `ground:false` / `centerXZ:false` opt out, `axisConversion:false` disables the rewrite but still reports the measured box. When every node's linear part is the identity (true for our helper output: pure translations only), the whole transform is **baked into POSITION** (`NORMAL`/`TANGENT` get the rotation only) and node translations get rotated — this keeps `accessor.min/max` equal to the real box, which Cesium uses for framing. If any node carries a rotation/scale it falls back to `mode: 'root'`: one wrapper node holding the conversion matrix, vertices untouched. `built.conversion` reports `mode` (`bake`/`root`/`none`), `label` (Chinese, e.g. `Z-up→Y-up + 贴地 + 水平归心`), and `before`/`after` boxes; `convertIveToGlb` surfaces them as `report.axis` / `report.axisMode` / `report.worldSize` / `worldCenter` / `worldMin`, which `main.js` forwards in the `convert-done` payload for the log line.
- **`matrix` presence, not `hasMatrix`, is the only valid test** (BR-016). The helper omits the field entirely for identity matrices and never writes a `hasMatrix` boolean, so `node.hasMatrix` is always `undefined` in JS — gating on it silently dropped every node translation and left the hat/body parts of 蹲姿 floating below the figure (world Y `-0.81..-0.54` instead of `1.06..1.36`). Use `nodeMatrixOf(node)`.
- **Helper resolution** (`resolveIveHelper`) tries `GLB_REPAIR_IVE2GLB`, then `vendor/ive2glb/<platform>-<arch>/ive2glb[.exe]`, then the same path with `app.asar` → `app.asar.unpacked` (the binary must be `asarUnpack`ed — nothing inside an asar can be executed). When nothing is found, `convertIveToGlb` returns `status: 'error'` with a Chinese message listing every path searched (BR-012); the renderer surfaces this at startup through the `app-capabilities` channel.
- **Vertices are welded** by default (`weldVertices: false` to opt out, BR-017). The helper emits triangle soup — 18,924 faces came out as 56,772 vertices (exactly 3 per triangle), inflating the vertex buffers ~5×. `weldVertices()` merges only vertices whose **every attribute value is identical** (key = all components of all streams joined with `String()`, which also collapses `-0` onto `0` — the axis rotation introduces `-0`, and a bit-exact comparison would leave needless duplicates). Because the key covers every attribute, UV seams and hard edges survive: 蹲姿 56,772 → 11,516 vertices (−79.7%, the same count FBX2glTF produces) with faces/textures untouched, 3.81 MB → 2.43 MB. Verified by comparing the two outputs triangle-by-triangle: the multiset of triangles, each keyed by all three corners' full attribute tuples under winding-preserving cyclic rotation, is **identical for all 18,924 faces**. `weldVertices` returns `null` (streams left untouched) when nothing merges or when an index is out of range. Welding runs **before** the axis conversion so the transform only touches surviving vertices; `convertIveToGlb` reports `vertices` / `verticesBefore` / `weldedVertices` / `triangles`, with `vertices` always counted from the written JSON so it stays meaningful when welding is off.
- **Vendoring** is `scripts/build-ive2glb.sh` (macOS): build, copy the executable plus the transitive closure of non-system dylibs into `lib/`, copy `osgdb_ive.so`/`osgdb_serializers_osg.so` into `osgPlugins/`, rewrite absolute Homebrew paths to `@rpath/...`, add `-rpath @executable_path/lib`, then **ad-hoc re-sign everything** (`install_name_tool` invalidates the signature and arm64 kills unsigned binaries). Verify isolation with `DYLD_PRINT_LIBRARIES=1 vendor/ive2glb/darwin-arm64/ive2glb o-model/person-move.ive /tmp/out` — the Homebrew load count must be 0.
- `osgdb_ive.so` pulls in `libosgText/Sim/FX/Terrain/Volume/GA/Util` plus fontconfig/freetype (~11 MB vendored) — inherent to OSG's IVE plugin, not a packaging mistake.
- Measured on `o-model/person-move.ive` (28.5 MB): helper 1.5 s, full JS conversion ~2.5 s, output 2.43 MB GLB (11,516 vertices after welding) with 3 embedded JPEGs (a geometry-only OBJ route via `osgconv` produces a 600 KB texture-less shell — do not use it).

## Model inspection (`src/inspect.js` + `src/transform.js`)

Answers "how big is this model, how many vertices/faces, what textures does it have, where is its center, which way is up, what scale is it" — and, more importantly, surfaces the defects you cannot see by looking at the model:

- **Both boxes are measured over the default scene only** (`json.scene ?? 0`), matching how Cesium frames a model. Meshes no scene references are excluded and reported via `UNREFERENCED_MESHES` — including them produced a *false* 1000× deviation on a perfectly sane 1³ model. A GLB with no `scenes` at all gets `world: null` plus `NO_DEFAULT_SCENE` (no scene means nothing renders; never fall back to treating every node as a root, which silently drops parent transforms).
- **The world box must be computed, never read.** glTF's accessor `min`/`max` describe vertex data only and ignore node transforms; tooling that unions them (the old `getPositionBounds` in `main.js`) produced boxes off by **229,713×** on `装甲救护车` and **4,461×** on `运输车`. `bounds.world` walks the node chain accumulating matrices and re-packs the 8 corners; `bounds.accessorUnion` is reported alongside it purely so `bounds.deviationFactor` can quantify the lie (warn above 10×).
- **The up axis is only guessed, conservatively.** An exporter signature (FBX2glTF / assimp / Khronos / Blender) → `Y` at `medium` confidence. Bare bounding box → `unknown` at `low` with the extents as evidence, and an `UP_AXIS_UNCERTAIN` issue telling a human to decide. Never silently rewrite orientation.
- **Read-only and never throws** (BR-020): unreadable file, non-`.glb`, parse failure, **structurally malformed files** (`meshes:[null]`, `materials:{}`, `samplers:[null]`), missing accessor `min`/`max`, missing external image — all become Chinese issue entries (`level`/`code`/`message`); only the CLI exit code reflects failure. The analysis pass is wrapped in `try/catch` and flags `partial`, and element access goes through `asArray()`/optional chaining — an independent review caught five malformed-GLB shapes that made `inspect()` throw and the CLI crash.
- **Texture headers are parsed to the SOF, never truncated** (BR-022): a JPEG's SOF often sits behind a multi-KB APP1/Exif segment, so capping the scan at 1 KB left **62% of the sample corpus's embedded textures** without dimensions — silently disabling the NPOT and 1×1 checks. Data URIs are decoded from a prefix and parsed the same way.
- **The deviation factor covers size *and* position**: `max(worst per-axis size ratio, 1 + center offset ÷ diagonal)`. Size alone returns 1 for a pure translation, which still mis-frames the model. `deviationParts` exposes both components. Degenerate detection uses a column-length ratio (`shortest ÷ longest < 1e-6`) rather than `|det|`, because a determinant is a volume measure: `|det| < 1e-12` false-positives on legitimate 1e-5 uniform scales and misses single-axis squash (BR-023).
- Issue codes worth knowing: `ACCESSOR_BOUNDS_UNRELIABLE`, `TRIANGLE_SOUP` (vertex/triangle ratio ≈ 3), `TEXTURE_1X1_PLACEHOLDER`, `NO_SAMPLED_TEXTURE` (materials exist but nothing samples a texture), `NPOT_WITH_REPEAT_MIPMAP`, `MISSING_TEXCOORD` (error level — stops Cesium rendering the whole scene), `MIRRORED_NODES`, `SINGULAR_NODES`, `UP_AXIS_UNCERTAIN`.
- Measured on the sample corpus (at the time of measurement: 18 files in `o-model/` + 3 in `model/`; one sample is literally named `装甲救护车 .glb` **with a trailing space**): 0 crashes, slowest 11 ms (`M1A2艾布拉姆斯坦克.glb`, 174,937 vertices) against a 2 s budget. The corpus is **gitignored local data whose size varies** — the corpus test scales its assertions to whatever is present (it once hardcoded `>= 20` files and failed as soon as the samples were trimmed) instead of pinning a count. `vertexReuseRatio` is defined as **vertices ÷ triangles** — 3.0 means unwelded triangle soup, 0.61 is the welded `model/蹲姿.glb` reference.

## Electron shell & IPC contract

- **Main process** (`src/main.js`) owns the frameless `BrowserWindow`, the custom title bar (min/max/close), native dialogs, and validation-pane reads. IPC handlers: `pick-inputs` (filters `glb` + `ive` + `fbx` + `obj`), `pick-output-dir`, `app-capabilities` (reports both `ive` and `assimp` availability for this platform), `repair-glb` (converts any `.ive`/`.fbx`/`.obj` inputs to temp GLBs via `convertSourceToGlb`, disambiguating same-stem sources so two conversions cannot overwrite each other, then calls `repairMany` on the GLBs), `read-glb-data-url` (converts non-GLB input to a temp GLB first; returns the GLB as a base64 `data:model/gltf-binary` URL plus `bounds` from accessor min/max and a `metadata` summary), `inspect-glb` (single-file 体检; `.ive` is converted to a temp GLB first, the temp dir is removed in `finally`; **never rejects** — it always resolves to `{ ok: true, filePath, sourcePath, report }` or `{ ok: false, filePath, error }`), and the window controls. `BrowserWindow` uses `contextIsolation: true` and `nodeIntegration: false`.
- **Preload** (`src/preload.js`) is the only bridge — it exposes `window.repairApp` wrapping each `ipcRenderer.invoke`. The renderer has no Node access; any new capability must be plumbed as a channel here + a handler in `main.js`.
- **Renderer** (`src/renderer.js` + `index.html` + `styles.css`) is dependency-free DOM scripting, laid out as an **editor-style shell** (BR-027): CSS Grid with a left queue pane, the Cesium viewport as the widest middle pane, a right 体检/inspector pane, a collapsible bottom log pane and a status bar. 4px splitters drag the CSS variables and persist them to `localStorage` under the key `glb-repair.layout` (clamped on read), the 3D container is watched by a `ResizeObserver` that calls `viewer.resize()` (Cesium itself only listens to *window* resize), and narrow windows fall back to two panes with a collapsible right drawer. No framework, no bundler. Three functional areas: the repair queue/results panel; the 体检 panel (two columns 世界盒/accessor 盒 + deviation warning + fact rows + sorted issue list — inspection is fired in parallel with the preview load and a token guard drops stale results when the user switches models quickly; a failed inspection only paints the panel, it never blocks the preview); and the Cesium validation view which creates a `Cesium.Viewer`, loads the chosen GLB via `Cesium.Model.fromGltfAsync` on the data URL, frames the camera from the bounding sphere / accessor bounds, and logs bounding-sphere/camera/animation/render diagnostics to the log pane. After a successful batch run it auto-validates the first success. The 预览方向/缩放/上轴 controls (`#previewYaw`/`#previewScale`/`#previewAxis`) set `state.model.modelMatrix` via `previewMatrix()` and log the final matrix — preview-only, never written back (BR-024). Because a hidden window gets its rAF throttled and Cesium then renders zero frames, the window disables `backgroundThrottling` and `waitForModelReady` times out into an explicit 「未渲染」 status rather than a false 「加载成功」 (BR-026). If you touch Cesium preview framing, `docs/cesium-glb-load-issues.md` explains why conservative near-plane and bounds-based framing matter.

## Conventions & house rules

- CommonJS modules, 2-space indent, short functions, lowercase-hyphen filenames (`scripts/ensure-cesium.js`, `refs/scripts/repair-casualty-glb-textures.cjs`). No bundler, no TypeScript, no framework.
- Keep new runtime code under `src/`; experimental/reference material goes in `refs/` or `docs/`.
- When behavior changes, update `docs/001-code-design.md` (module/interface tables, BR rules). Do not overwrite `AGENTS.md`.
- `docs/` holds the design docs (`001-code-design.md`, `002-requirements.md`, `cesium-glb-load-issues.md` — tracked) plus the platform artifacts the workflow depends on (`requirements/REQUIREMENTS.md`, `requirements/TASKS.md`, `PROJECT_MEMORY.md`, `approvals/APPROVALS.md`, `testing/TEST_PLAN.md`, `testing/PERF_BUDGET.md`, `release/RELEASE_CHECKLIST.md`, `release/MERGE_REQUEST.md`, `design/ADR.md`, `api/openapi.json` — **also tracked**, see the `.gitignore` policy above). Treat the three design docs as living reference and update `001-code-design.md`'s BR table whenever behavior changes.
