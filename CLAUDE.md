# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

An Electron + plain-Node desktop tool that repairs GLB (glTF 2.0 binary) models that open fine in 3D viewers but fail to render in Cesium, then previews the result in a bundled local Cesium. The core is a **hand-written GLB binary parser/repacker with no third-party glTF libraries** — all format handling lives in the code, not in a dependency.

The app is split into two layers:

- `src/repair.js` — the repair engine. Pure Node (CommonJS), no Electron or npm runtime deps, so it runs and tests under plain `node`.
- `src/ive.js` — the IVE→GLB converter: drives the native `ive2glb` helper and assembles a self-contained GLB in Node. Also pure Node (uses only `jpeg-js`/`pngjs` plus `repair.js`'s `writeGlb`/`align4`).
- `native/ive2glb/` — a small C++20 helper that reads IVE with OpenSceneGraph and dumps `scene.json` + `data.bin`. See "IVE input pipeline" below.
- `src/main.js` + `src/preload.js` + `src/renderer.js`/`index.html` — the standard Electron main/preload/renderer shell over IPC.

**All UI strings, log lines, and thrown error messages are Chinese (zh-CN);** keep new user-facing strings Chinese for consistency. The design doc (`docs/001-code-design.md`) and issue analysis (`docs/cesium-glb-load-issues.md`) are Chinese too.

## Commands

- `npm install` — installs the Electron dev toolchain.
- `npm run build:ive2glb` — builds `native/ive2glb` and vendors a **self-contained** helper into `vendor/ive2glb/darwin-<arch>/` (executable + `lib/*.dylib` + `osgPlugins/`), rewriting deps to `@rpath` and ad-hoc re-signing. macOS only; the Windows steps are in `native/ive2glb/README.md`.
- `npm run dev` / `npm start` — runs `ensure:cesium` then launches Electron (app entry is `src/main.js`).
- `npm run ensure:cesium` — downloads the Cesium 1.128 release zip and unpacks it to `vendor/cesium/1.128/Build/Cesium/` only if `Cesium.js` + `Widgets/widgets.css` are missing. Needed before `dev`/`start` because `index.html` loads Cesium from that exact relative path as a plain global `<script>` (no bundler).
- `npm run lint` — `node --check` (syntax check only) over the five `src/*.js` files. Not a style linter.
- `npm test` — Node's built-in test runner (`node --test`), which discovers `test/*.test.js`. The suite is committed, but the **sample models are not**: on a fresh checkout exactly **11 tests skip and 0 fail (measured: `pass 33 / skipped 11`)** — 6 in `repair.test.js` that need `refs/models/*`, and 5 in `ive.test.js` that need `o-model/*.ive`. Each skipped test prints the missing files *and* the recovery command after the `#` (Node substitutes the reason for the literal `# SKIP`), e.g. `﹣ collectGlbFiles finds nested glb files (0.05ms) # 缺少测试夹具 refs/models/{…}；恢复：mkdir -p refs/models && cp o-model/*.glb refs/models/`. Every test that builds its own synthetic fixture still runs. All three suites use the same `fixtureSkipReason()` pattern — keep it that way, because a committed suite that hard-fails on a clean clone is worse than one that skips.
- Run one test file: `node --test test/repair.test.js` (or `test/ive.test.js`). Filter by name: `node --test --test-name-pattern='external PNG'`.
- Restore the test fixtures: `mkdir -p refs/models && cp o-model/*.glb refs/models/`. Both suites hard-code `refs/models/{person-stand,person-move,蹲姿}.glb`; those three files (6.5 MB total) live in the top-level `o-model/` (gitignored, alongside the `.ive` inputs and the `*-from-fbx` / `*-from-obj` reference exports), and `refs/` does not exist in a fresh checkout. Without them 11 tests (6 in `repair.test.js`, 5 in `ive.test.js`) skip with this exact recovery command in place of `# SKIP` — they no longer fail. (`model/` exists but only holds a spare repaired `person-move.glb` — it is not `o-model/`.)
- `npm run dist:win` — `electron-builder` Windows x64 NSIS + portable into `dist/`.

**Image transcoding is self-contained:** the remaining transcode path (JPEG→PNG when `keepJpeg: false` or for CMYK JPEGs) runs in-process via the `jpeg-js` + `pngjs` production dependencies (`encodePng` in `src/repair.js`). Do NOT shell out to an external binary like `ffmpeg` here — packaged end-user apps have none, which produced `spawnSync ffmpeg ENOENT`. `jpeg-js`/`pngjs` must stay under `dependencies` (not `devDependencies`) or electron-builder won't package them into the asar.

Several directories the code depends on are **gitignored and present only locally**: `o-model/` (~174 MB of sample models: the `.ive` inputs plus every `*-from-fbx` / `*-from-obj` reference export, and the only copy of the three `refs/models/` test fixtures), `model/` (scratch landing zone for repaired GLBs), `vendor/cesium/` (downloaded by `ensure:cesium`), `.workbuddy/` (agent scratch), and `refs/` (not present at all in this checkout, though `docs/001-code-design.md` §8 and `test/repair.test.js` still reference it). After a fresh clone, `npm run dev` regenerates `vendor/cesium/`; without the sample models the 11 tests that need them skip with a clear reason instead of failing.

**What goes into git** (`.gitignore` policy): source in, artifacts out. `native/ive2glb/**` (C++ sources, `CMakeLists.txt`, README) and `scripts/build-ive2glb.sh` are source and must be committed — they are the only way to reproduce the helper. `native/ive2glb/build/` (CMake output) is ignored. `vendor/ive2glb/<platform>-<arch>/` is a **vendored distribution artifact that `package.json`'s `asarUnpack` + `files` require at packaging time**; it is deliberately *not* ignored, because the build script is macOS-only and there is no CI to produce it. Keep packaging ignores directory-scoped (`dist/`, `release/`, `out/`) — never add a blanket `*.exe` / `*.zip`, or a future `vendor/ive2glb/win32-x64/ive2glb.exe` would be silently dropped from the installer. `test/` is tracked source (the whole `node --test` suite is committed, and both test files skip themselves when the gitignored fixtures are absent). `docs/` is still ignored by an **older convention of this repo** — `docs/001-code-design.md` / `docs/002-requirements.md` are local-only today — so nobody pays the hidden cost of breaking the test suite without noticing. Do not re-add a `test/` line to `.gitignore`.

`scripts/ensure-cesium.js` unpacks the Cesium zip with `execFileSync('unzip', ...)`, so it assumes a POSIX `unzip` on PATH — it works on macOS/Linux but not on a bare Windows host, even though `dist:win` targets Windows.

## Repair pipeline (`src/repair.js`)

`repairGlbFile(inputPath, outputPath)` reads a GLB, mutates the parsed JSON + BIN in place, and writes a new file. One call repairs one file and **never throws** — it returns a `report` object with `status: 'success' | 'error'` and a Chinese `error` message on failure, so `repairMany` (batch/directory scan) keeps going past bad files. A repaired file keeps the original's basename in the chosen output dir (BR-001).

Steps run in this order; each has byte-layout consequences:

1. **`bakeSkinnedMeshes`** — bakes skinned primitives (mesh nodes with `skin`; `JOINTS_0`/`WEIGHTS_0` attrs) to static ones. It does its own node/scene walk (`computeNodeGlobalMatrices`), TRS→matrix and 4×4 inverse math, and per-vertex skinning with up to 4 influences using `inverseBindMatrices`. Rewrites POSITION/NORMAL accessor bytes and **recomputes `accessor.min`/`max`** (Cesium reads these for culling/framing — stale bounds are a root cause of "loads but invisible"). Strips `JOINTS_0`/`WEIGHTS_0`, and if any mesh was baked, deletes `skins` and `animations`.

   **Pose freezing:** by default it bakes to the **bind pose** — so an animated character whose action (e.g. a crouch) lives only in its animation clip would collapse to the standing bind pose. Pass `options.poseTime` (a number of seconds, or `'start'`/`'end'` of animation index `options.animationIndex`, default 0) to first sample the glTF animation (LINEAR slerp/lerp + STEP are handled via `computePosedLocalMatrices`/`sampleAnimationChannel`) and bake in that posed frame instead. The app exposes this as the "烘焙为动画起始姿势" checkbox (`freezePose` → `poseTime: 'start'`). A file with no animation is unaffected (resolves to `null`).
2. **Image normalization** — for each `image`, either read its `bufferView` bytes out of the BIN, or resolve an external `uri` via `resolveExternalImage`. **PNGs pass through untouched, and JPEGs are kept byte-for-byte as `image/jpeg` by default** (`options.keepJpeg`, default on; the UI exposes it as the 「保留 JPEG 贴图原格式」 checkbox) — re-encoding a photographic JPEG to lossless PNG inflates it ~5× (measured: 2048² 2.1MB → 10.25MB), which was blowing up repaired models. JPEGs only go through `encodePng` (`jpeg-js` decode → `pngjs` encode) when `keepJpeg: false`, or when `jpegComponentCount` reports a 4-component CMYK/YCCK JPEG (browsers decode those badly, so keeping them would produce a broken texture); an unparseable component count also falls back to transcoding rather than passing through blind. Any other image format throws a per-file error telling the user to supply PNG/JPEG. Embedded JPEGs that pass through register **no `replacements` entry** (the bytes did not change) and just get their `mimeType` set. `resolveExternalImage` handles data URIs, absolute paths (incl. Windows `C:\...`), relative paths, and recursive by-name search next to the GLB (catches `.fbm` folders). A missing external image throws a recovery message telling the user to place the file / its `.fbm` dir beside the GLB.
3. **`stripSpecularExtensions`** — removes `KHR_materials_specular` from `extensionsUsed`, `extensionsRequired`, and per-material `extensions` (empty arrays/objects are deleted, not left as `[]`/`{}`).
4. **`fillMissingTexCoords`** — for a primitive whose material samples a texture (any of `baseColorTexture` / `metallicRoughnessTexture` / `normalTexture` / `occlusionTexture` / `emissiveTexture` / a `*Texture` in an extension) at `texCoord: n` but which has no `TEXCOORD_n` attribute, appends a zero-filled float32 `VEC2` accessor sized to the primitive's `POSITION.count`. Such primitives otherwise make Cesium generate a fragment shader referencing an undeclared varying — the compile failure stops rendering for the **whole scene**, not just that model.
5. **`mergePrimitivesByMaterial`** — the Cesium scalability fix. Cesium 1.128's model load time grows super-linearly with primitive count (measured: 6 prims 0.6s, 50 prims 9.3s, 100+ never finishes). When a file has more than `options.mergePrimitiveThreshold` primitives (default 100), primitives sharing a material and an attribute format are merged into one, baking each mesh node's **world matrix** into POSITION (via `transformPoint`) and NORMAL (via `transposeMatrix(invertMatrix(...))` + `transformVector`). Zero-filled `TEXCOORD_n` is synthesized for members lacking it, so UV presence never splits a group. **Triangle winding is reversed per primitive when `determinant3(world) < 0`** — many of these models use mirrored nodes and every material is `doubleSided`, so skipping this inverts lighting without changing the silhouette. Merged indices are always `uint32`. New streams go into **appended** bufferViews (never reuse a source view: an accessor can be shared across material groups). Consumed meshes get `primitives: []` (not just the surviving one) because `getPositionBounds` in `main.js` unions every mesh's POSITION `min`/`max` with no node-transform awareness. Scene restructuring appends an identity root node holding the merged mesh, so no existing index needs remapping. It **skips** (whole file, no-op) on Draco/meshopt, morph targets, animations, skinned bakes, instanced meshes, non-TRIANGLES modes, non-float32 attributes, sparse accessors, interleaved views, multi-buffer files, or nodes unreachable from the default scene. **`repairGlbFile` additionally skips the merge entirely when `bakeSkinnedMeshes` baked anything**, because the bake writes only to `replacements` and not to `bin` — merging would then read pre-bake bind-pose vertices.

   Its companion **`reclaimConsumedViews`** zeroes out the bufferViews whose data the merge consumed (registers `Buffer.alloc(0)` for each), skipping any view still referenced by another accessor, a skin, an animation, or an image. That is what keeps the merged output from carrying the old per-primitive vertex bytes. Both run inside the merge step, before `rebuildBinary`.
6. **`rebuildBinary`** — the repack pass. BufferView bytes that changed are supplied as a `Map<bufferViewIndex, Buffer>` (from steps 1–2, 4–5). It sorts views by original `byteOffset`, re-emits gaps as-is, **keeps every 4-byte alignment**, and rewrites each `bufferView.byteOffset`/`byteLength` and `buffers[0].byteLength`.
7. **`appendBufferViewToBinary`** — external or newly-converted external images (now PNG) are appended as new `bufferView`s; their `uri` is deleted and `mimeType` set to `image/png`. Steps 4–5 use the same helper to append merged/UV bytes.

Appending steps thread a `workingBin` (`let workingBin = bin`) and register their new bytes in `replacements`, because `rebuildBinary` copies any view absent from the map straight out of the bin it is handed. `mergePrimitivesByMaterial` reads and appends against the same `workingBin`, so it sees the UV accessors step 4 just added.

Format invariants that are easy to break (there are helper tests but no golden-binary snapshot tests):

- GLB container: 12-byte header (`glTF`, version 2), JSON chunk padded with spaces `0x20` to a 4-byte boundary, BIN chunk padded to 4; all lengths little-endian. `readGlb`/`createGlbBuffer`/`writeGlb` encode this.
- Only **non-interleaved** bufferViews are supported — a view with `byteStride` throws (`readAccessorData`).
- Accessor `min`/`max` must stay in sync whenever you rewrite POSITION data.
- `align4`, matrix helpers (`identityMatrix`, `multiplyMatrix`, `invertMatrix`, `transformPoint`, `transformVector`, `getNodeLocalMatrix`, `getTypedArrayConstructor`, `readAccessorData`) are exported/testable primitives used by the bake.
- **`readGlb` returns `bin` as a `subarray` view aliasing the input file buffer, not a copy.** Treat it as read-only — an in-place write would mutate the aliased source bytes. The derived buffers (`workingBin`, appends) are separate allocations, so the append-then-read-by-original-offset pattern in steps 4–5 stays valid.
- **`writeGlb` streams** the header/JSON/BIN sections with `fs.writeSync` rather than materializing a second full-size GLB; `createGlbBuffer` is still exported for callers that need an in-memory GLB. This, the `subarray` above, and `appendExternalImages` (which appends all external images in one `Buffer.concat` instead of one full-BIN copy per image) are deliberate memory measures for large batches — a return to copy-per-step will regress peak memory on multi-hundred-MB models.

The batch entry points `collectGlbEntries(inputPaths, extensions = ['.glb'])` (returns `{ inputPath, relativePath }`, preserving nested structure under a directory root) and `collectGlbFiles` mirror the earlier standalone scripts under `refs/scripts/` — those `refs/` originals are the pre-productization versions of this logic and are no longer in the checkout (see the gitignored-directories note above), but `docs/001-code-design.md` §8 still lists them. The optional `extensions` argument is how `main.js` scans directories for both `.glb` and `.ive` without making `repairMany` itself aware of IVE. `repairMany` also accepts **`options.entries`**: when given, it skips its own scan and uses that entry list. `main.js` relies on this — it must NOT flatten the scanned entries into a list of absolute file paths before calling `repairMany`, because that loses the directory-relative `relativePath` and nested inputs land in the output root.

## IVE input pipeline (`src/ive.js` + `native/ive2glb`)

IVE is OpenSceneGraph's private serialized scene format. **There is no JS/WASM IVE parser** (npm only has `.osgb/.osgt` serializer libraries), so reading IVE requires native OSG code. The design keeps that native part thin and leaves all format authoring in Node:

```
input.ive ──▶ ive2glb (C++/OSG) ──▶ <tmp>/scene.json + data.bin
                                        │
                      src/ive.js (Node) ─┴─▶ self-contained GLB ──▶ repairMany ──▶ Cesium preview
```

- **`native/ive2glb/src/main.cpp`** links only `libosg`/`libosgDB` (no Qt, Assimp, `osgViewer`, `osgGA`, or GL context). It walks the scene graph with its own recursive `Builder::addNode`, converts every vertex attribute to float32 and every index to uint32, expands strips/fans/quads/polygons into triangles, and writes `scene.json` (nodes, materials, image metadata, byte ranges) plus `data.bin`. It prints one line of JSON on stdout (`{"status":...,"images":...,"binBytes":...}`) and exits non-zero on failure. `registerLocalPluginPath()` **inserts** the bundled `osgPlugins/` at the **front** of `osgDB::Registry`'s library path list — `push_back` is not enough, because OSG's compiled-in plugin path (the dev machine's Homebrew install) wins and the vendored libs never load.
- **`src/ive.js`** runs the helper via `spawnSync` into a temp dir, then assembles the GLB with `writeGlb`/`align4` from `repair.js`: bufferViews for attributes (`ARRAY_BUFFER`), indices (`ELEMENT_ARRAY_BUFFER`) and images (no `target`), plus POSITION `min`/`max` computed from the dumped floats (Cesium needs them for framing). Materials map `Material.diffuse` → `baseColorFactor`, `Texture2D` unit 0 → `baseColorTexture`, `roughnessFactor` from `sqrt(2/(shininess+2))`, and `doubleSided: material.cullFace === 'absent'` (an absent `CullFace` means GL culling was off).
- **Pixel orientation is the trap.** `osg::Image` stores rows bottom-up (`origin: BOTTOM_LEFT`, OpenGL convention) while PNG/JPEG are top-down. `readImagePixels()` reads rows in reverse when `origin !== 'TOP_LEFT'`. Verified against the reference `.fbm` JPEG: correct orientation gives a row-0 MAE of ~0.5; skipping the flip jumps to ~35.
- **Textures are always embedded** (`bufferView` + `mimeType`, no external `uri`). `keepJpeg` (default on) selects JPEG at `jpegQuality` 90; images with an alpha channel force PNG because JPEG would drop transparency. Non-power-of-two images fall back to `CLAMP_TO_EDGE` + `LINEAR` (mipmapped `REPEAT` is invalid for NPOT).
- **Empty subtrees are pruned** by default (`pruneMeshlessSubtrees`): IVE files typically carry a whole `mixamorig:*` bone hierarchy that renders nothing (72 nodes → 7 for `person-move.ive`). Pass `pruneMeshlessNodes: false` to keep them.
- **IVE is Z-up, glTF is Y-up** (BR-013/014/015). Without the `-90°` about X rotation baked in, models arrive in Cesium lying down (蹲姿: `0.538 × 1.056 × 1.171` instead of the reference's `0.538 × 1.364 × 1.056` — Y/Z swapped). `createAxisConversion` computes the **world AABB by walking the node chain accumulating matrices** (never from accessor min/max — those ignore node transforms and were off by up to 90,000×), then rotates it, then sets `T = (-centerX, -minY, -centerZ)` so the model lands grounded and horizontally centered; `ground:false` / `centerXZ:false` opt out, `axisConversion:false` disables the rewrite but still reports the measured box. When every node's linear part is the identity (true for our helper output: pure translations only), the whole transform is **baked into POSITION** (`NORMAL`/`TANGENT` get the rotation only) and node translations get rotated — this keeps `accessor.min/max` equal to the real box, which Cesium uses for framing. If any node carries a rotation/scale it falls back to `mode: 'root'`: one wrapper node holding the conversion matrix, vertices untouched. `built.conversion` reports `mode` (`bake`/`root`/`none`), `label` (Chinese, e.g. `Z-up→Y-up + 贴地 + 水平归心`), and `before`/`after` boxes; `convertIveToGlb` surfaces them as `report.axis` / `report.axisMode` / `report.worldSize` / `worldCenter` / `worldMin`, which `main.js` forwards in the `convert-done` payload for the log line.
- **`matrix` presence, not `hasMatrix`, is the only valid test** (BR-016). The helper omits the field entirely for identity matrices and never writes a `hasMatrix` boolean, so `node.hasMatrix` is always `undefined` in JS — gating on it silently dropped every node translation and left the hat/body parts of 蹲姿 floating below the figure (world Y `-0.81..-0.54` instead of `1.06..1.36`). Use `nodeMatrixOf(node)`.
- **Helper resolution** (`resolveIveHelper`) tries `GLB_REPAIR_IVE2GLB`, then `vendor/ive2glb/<platform>-<arch>/ive2glb[.exe]`, then the same path with `app.asar` → `app.asar.unpacked` (the binary must be `asarUnpack`ed — nothing inside an asar can be executed). When nothing is found, `convertIveToGlb` returns `status: 'error'` with a Chinese message listing every path searched (BR-012); the renderer surfaces this at startup through the `app-capabilities` channel.
- **Vertices are welded** by default (`weldVertices: false` to opt out, BR-017). The helper emits triangle soup — 18,924 faces came out as 56,772 vertices (exactly 3 per triangle), inflating the vertex buffers ~5×. `weldVertices()` merges only vertices whose **every attribute value is identical** (key = all components of all streams joined with `String()`, which also collapses `-0` onto `0` — the axis rotation introduces `-0`, and a bit-exact comparison would leave needless duplicates). Because the key covers every attribute, UV seams and hard edges survive: 蹲姿 56,772 → 11,516 vertices (−79.7%, the same count FBX2glTF produces) with faces/textures untouched, 3.81 MB → 2.43 MB. Verified by comparing the two outputs triangle-by-triangle: the multiset of triangles, each keyed by all three corners' full attribute tuples under winding-preserving cyclic rotation, is **identical for all 18,924 faces**. `weldVertices` returns `null` (streams left untouched) when nothing merges or when an index is out of range. Welding runs **before** the axis conversion so the transform only touches surviving vertices; `convertIveToGlb` reports `vertices` / `verticesBefore` / `weldedVertices` / `triangles`, with `vertices` always counted from the written JSON so it stays meaningful when welding is off.
- **Vendoring** is `scripts/build-ive2glb.sh` (macOS): build, copy the executable plus the transitive closure of non-system dylibs into `lib/`, copy `osgdb_ive.so`/`osgdb_serializers_osg.so` into `osgPlugins/`, rewrite absolute Homebrew paths to `@rpath/...`, add `-rpath @executable_path/lib`, then **ad-hoc re-sign everything** (`install_name_tool` invalidates the signature and arm64 kills unsigned binaries). Verify isolation with `DYLD_PRINT_LIBRARIES=1 vendor/ive2glb/darwin-arm64/ive2glb o-model/person-move.ive /tmp/out` — the Homebrew load count must be 0.
- `osgdb_ive.so` pulls in `libosgText/Sim/FX/Terrain/Volume/GA/Util` plus fontconfig/freetype (~11 MB vendored) — inherent to OSG's IVE plugin, not a packaging mistake.
- Measured on `o-model/person-move.ive` (28.5 MB): helper 1.5 s, full JS conversion ~2.5 s, output 3.99 MB GLB with 3 embedded JPEGs (a geometry-only OBJ route via `osgconv` produces a 600 KB texture-less shell — do not use it).

## Electron shell & IPC contract

- **Main process** (`src/main.js`) owns the frameless `BrowserWindow`, the custom title bar (min/max/close), native dialogs, and validation-pane reads. IPC handlers: `pick-inputs` (filters `glb` + `ive`), `pick-output-dir`, `app-capabilities` (reports whether IVE conversion is available for this platform), `repair-glb` (converts any `.ive` inputs to temp GLBs, then calls `repairMany` on the GLBs), `read-glb-data-url` (converts `.ive` to a temp GLB first; returns the GLB as a base64 `data:model/gltf-binary` URL plus `bounds` from accessor min/max and a `metadata` summary), and the window controls. `BrowserWindow` uses `contextIsolation: true` and `nodeIntegration: false`.
- **Preload** (`src/preload.js`) is the only bridge — it exposes `window.repairApp` wrapping each `ipcRenderer.invoke`. The renderer has no Node access; any new capability must be plumbed as a channel here + a handler in `main.js`.
- **Renderer** (`src/renderer.js` + `index.html` + `styles.css`) is dependency-free DOM scripting. Two functional areas: the repair queue/results panel, and the Cesium validation view which creates a `Cesium.Viewer`, loads the chosen GLB via `Cesium.Model.fromGltfAsync` on the data URL, frames the camera from the bounding sphere / accessor bounds, and logs bounding-sphere/camera/animation/render diagnostics to the log pane. After a successful batch run it auto-validates the first success. If you touch Cesium preview framing, `docs/cesium-glb-load-issues.md` explains why conservative near-plane and bounds-based framing matter. On startup it calls `repairApp.capabilities()` and shows a hint when IVE support is missing.
- **Progress is a push channel, not a return value.** The `repair-glb` handler attaches an `options.onProgress` that forwards each event to `event.sender.send('repair-progress', ...)`; the renderer subscribes through `repairApp.onRepairProgress`. `repairMany` is `async` *only* so it can `await setImmediate` once per file — the repair work itself is synchronous CPU, so without that yield the main process never returns to the event loop and no progress reaches the UI. The IVE stage reuses the same channel with `convert-start` / `convert-done` phases (emitted by `main.js`, not by `repairMany`). The event `phase` payloads are tabulated in `docs/001-code-design.md` §4.1.1.
- **`index.html` loads Cesium as a plain global `<script>`** (setting `window.CESIUM_BASE_URL` first) — no bundler — so the relative `../vendor/cesium/1.128/Build/Cesium/` path in both the script tag and the widget stylesheet is load-bearing. The page also carries a strict `Content-Security-Policy` meta tag; adding a CDN script or inline style means editing that policy, not just adding the tag.

## Conventions & house rules

- CommonJS modules, 2-space indent, short functions, lowercase-hyphen filenames (`scripts/ensure-cesium.js`, `refs/scripts/repair-casualty-glb-textures.cjs`). No bundler, no TypeScript, no framework.
- Keep new runtime code under `src/`; experimental/reference material goes in `refs/` or `docs/`.
- When behavior changes, update `docs/001-code-design.md` (module/interface tables, BR rules). Do not overwrite `AGENTS.md` — note that it is stale (it still describes `npm run lint`/`npm test` as placeholder commands that only print a message, and points at `refs/`), so trust this file over it.
- `docs/` is design/analysis documentation, not tracked in git here; treat it as living reference.
