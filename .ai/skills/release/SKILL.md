# Release — 交付与发布

把"代码合并了"变成"**可安全交付、可回滚**"。发布是**有预案**的动作，不是一次性命令。

## 何时使用

- 功能验收通过、准备合入发布分支或上线时
- 涉及数据库迁移、配置变更、依赖升级、外部接口变更时（**必须**有回滚预案）

## 环境分层

| 环境 | 用途 | 门禁 |
| :-- | :-- | :-- |
| local | 本地开发 | 快速反馈，允许 mock |
| staging | 发布前验证 | 与生产同构；跑冒烟 + 迁移演练 |
| production | 生产 | 需人工确认闸门 ③；发布后监控 |

**逐级晋升**：未在 staging 验证通过的产物不得进 production；同名产物逐级晋升，不重复构建。

## 发布流程

1. **预检（Preflight）**：按 `templates/RELEASE_CHECKLIST.md` 逐项核对，列出阻断项；缺项即停。
2. **迁移**：DB/配置/依赖变更**先于**代码发布；迁移脚本必须**可重入**且**可回滚**（含 down 脚本或补偿方案）。
3. **发布**：记录产物版本/commit、执行命令、目标环境；优先灰度或 feature flag 控制暴露面。
4. **冒烟（Smoke）**：跑关键路径（登录、主流程、支付等）并**留证据**（命令 + 结果）。
5. **回滚预案**：写明**触发条件**（错误率、延迟、数据异常阈值）与**执行步骤**；不确定时先回滚再排查。
6. **发布说明**：面向用户的变更摘要 + 破坏性变更 + 迁移注意。

## 硬性要求

- **无回滚预案不发布**；涉及数据迁移的变更必须有数据层面的回退方案。
- 破坏性变更（接口/字段/协议）必须提前标注并给出兼容期。
- 凭证只经环境变量/密钥管理下发，**不入库、不入日志**。
- 发布证据（版本、命令、结果）回写到 `docs/release/RELEASE_CHECKLIST.md`。

## 禁止

- ❌ 直接在生产改配置/数据而不记录
- ❌ 无冒烟验证即宣布发布成功
- ❌ 迁移脚本不可重入或不可回滚
- ❌ 跳过 staging 直接上线
