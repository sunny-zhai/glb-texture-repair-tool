### 0.4 现有工具的覆盖缺口（读代码确认）

- `getGlbMetadata()` 只输出 6 个**计数** + 扩展 + 外部 uri → **无顶点数、无三角面数、无贴图分辨率与字节、无包围盒、无中心、无朝向、无缩放**。
- `getPositionBounds()` = accessor min/max 并集，**不含节点矩阵** → 实测偏差最高 **9 万倍**（装甲救护车 801km vs 真实 8.95m）；蒙皮件更夸张：`o-model/person-move.glb` accessor 并集 `0.019×0.004×0.016` m，真实 `1.894×1.848×0.38` m。
- 预览放置写死：`scale: 1`、`modelMatrix: Cesium.Matrix4.IDENTITY` → **朝向、中心、比例尺三项没有任何入口**。

## 1. 需求拆解与范围

**一句话目标**：让这批来自 3ds Max / OSG / FBX 管线的人物与装备模型，在 Cesium 中以**正确的朝向、位置、尺寸**稳定显示；并且工具能直接给出"是哪个参数不对"的证据，而不只是报"加载成功/失败"。

**用户与场景**：模型资产维护人员拿到别人导出的 GLB/IVE，需要在 3D 地球上摆正、摆对比例、确认不黑屏；批量处理（20+ 个文件，含 17 万顶点、363 图元的重模型）。

### 功能清单

| # | 需求 | 级别 | 实测依据 |
|---|---|---|---|
| A1 | **模型体检报告**：文件大小、顶点数、三角面数、顶点/面比、图元数、材质数、贴图清单（格式/分辨率/字节/占文件比/是否 NPOT/是否被采样）、节点数、蒙皮与动画数、扩展、生成器签名 | 必须 | 现在只有 6 个计数 |
| A2 | **世界包围盒与中心**：沿节点链累乘的尺寸/中心/半径；与 accessor 并集**并列显示**，偏差超阈值告警 | 必须 | 偏差 4000×~90000× |
| A3 | **默认方向修正**：上轴推断（Y/Z/X）+ 偏航/俯仰/滚轮调节 + 一键"卧→立"、"贴地"、"中心归零" | 必须 | D1、D2；FBX 链 55 个 ±90° 节点 |
| A4 | **比例尺控制**：单位推断（`scale` 节点统计 + 世界尺寸对照常识尺寸）、全局缩放系数、"按目标米数缩放" | 必须 | 2.541e-4 与 100 两种畸形缩放并存；人 1.8m 与车 12m 需同框 |

| B1 | **IVE→GLB**（已交付），本期补齐 D1/D2 | 必须 | 见 0.5 |

| C3 | 外部贴图内嵌（已有）+ Windows 绝对路径 / 非 UTF-8 乱码路径兜底 | 必须 | `from-obj` 的 uri 实测乱码 |
| C4 | 体积策略：JPEG 保留（已有）、最大边长下拉、量化 | 必须 | 2048² PNG→JPEG 实测约 1/5 |
| C5 | 图元合并（已有，阈值 100） | 保留 | M1A2 363 / 指挥车 353 / 装甲救护车 224 / 抢救车 121 图元均超阈 |
| C6 | 镜像 / 非均匀缩放 / 奇异矩阵**检测与报告**（现在只在合并时隐式翻绕序） | 必须 | 指挥车 191 镜像、319 非均匀 |

| X2 | 骨骼编辑、动画重定向、PBR 材质美化 | **不做** | 超出"加载可用性"目标 |

## 2. 技术选型

### ① 朝向 / 中心 / 缩放落在哪一层

| 方案 | 优点 | 缺点 | 风险 |
|---|---|---|---|
| (a) 只改 Cesium `modelMatrix`（预览层） | 零副作用、实时、可回退 | 导出物仍是错的，换引擎还得重调 | 低 |
| (b) 写回 GLB 根节点 `matrix` | 改动小 | **accessor min/max 与新盒不一致 → Cesium 剔除/取景继续错** | 高（正是现状病灶） |
| (c) 烘焙进顶点 + 重算 min/max | 彻底，任何引擎一致；顺带解决 C1 | 失去 TRS 结构；与蒙皮/动画冲突 | 中 |
| **推荐** | 预览用 (a) 实时交互；"应用到输出"用 (c)；(b) 仅用于纯朝向微调的过渡 | | |

### ② 上轴推断

- (a) 纯几何最长轴：**实测不可靠**——把卧姿人（Y=0.554/Z=2.218）和 M1A2（Z=11.98）都误判成 Z-up。
- (b) 节点矩阵统计（成簇的 ±90° 绕 X 旋转）：FBX 链 55 个 ±90° 绕 X，是强信号。
- (c) 生成器签名（`FBX2glTF 0.9.7` / `assimp v6.0.0` / `Blender I/O 4.2.57` / 无 generator）：语料 4 种签名并存，可作先验。
- **推荐 (b)+(c) 加权推断，UI 保留三态手动覆盖并记住选择**。事实：无法 100% 自动；推断：约 80% 语料可判对。

### ③ 世界包围盒：自研节点链遍历（复用 `repair.js` 已导出的 `getNodeLocalMatrix` / `multiplyMatrix` / `transformPoint`）。**否决**引入 three.js——与"手写 GLB、不依赖第三方 glTF 库"的既定哲学冲突，且增加 600KB+ 体积。

### ④ FBX/OBJ 后端（可选线）

| 候选 | 事实 | 判断 |
|---|---|---|
| `assimpjs@0.0.10`（WASM） | npm 实测：2023-07-13 发布，8.7MB/53 文件，导出目标含 `glb2`，可在 Node 加载 | **推荐**：平台无关，顺带解掉 Windows 二进制缺失 |
| 扩写 `native/ive2glb` 链 assimp | 复用现有 vendoring 机制 | 每平台一个二进制，Windows 仍卡住 |
| `osgconv`→OBJ→`assimp export` | **实测否决**：产 600,680B 空壳 GLB，MTL 内是 `images\…tga` 反斜杠路径，贴图全丢 | 不做 |

### ⑤ 贴图降采样

`jpeg-js` / `pngjs` 只做编解码、**无缩放**（事实）。选项：自研 box-filter（纯 JS，只对 2 的幂次降半）vs 引入 `sharp`（原生二进制，electron-builder 多平台分发风险）。**推荐自研半采样**，守住"包内不额外引入系统二进制"的既有约束。

## 3. 架构与数据

```
                     ┌── src/inspect.js（新，纯 Node）──── 体检报告 R
输入 GLB / IVE ──────┤
                     ├── src/transform.js（新）──────── 上轴推断/归心/贴地/缩放 → 烘焙选项 T
                     │
src/ive.js ──(D1/D2/D3)─┐
src/repair.js ──(C1/C2/C6)─┴─→ 输出 GLB ─→ read-glb-data-url ─→ Cesium 预览（modelMatrix = T）
```

| 模块 | 职责 | 关键接口 |
|---|---|---|
| `src/inspect.js` | 只读体检，**永不改写** | `inspectGlb(path) → Report` |
| `src/transform.js` | 朝向/中心/缩放计算与烘焙 | `analyzeUpAxis(json)`、`worldBounds(json)`、`applyTransform(json, bin, opts)` |
| `src/ive.js` | IVE 转换（本期改造） | 新增 `upAxis`、`ground`、`centerXZ`、`weldVertices` |
| `src/repair.js` | 修复管线（扩展） | 新步骤 `bakeNodeTransforms`、`normalizeTextures`、`auditTransforms` |
| `src/main.js` | IPC | 新增 `inspect-glb`、`preview-transform`；`read-glb-data-url` 返回值补 `report` |
| `src/renderer.js` | 预览面板 | 方向（偏航/俯仰/滚轮）+ 缩放 + 归心控件与"应用到输出" |

**Report 字段**（均可空，便于增量实现）：
`file.bytes` / `meshes` / `primitives` / `vertices` / `triangles` / `vertexReuseRatio` /
`textures[]{mime,w,h,bytes,sampled,npot}` / `textureBytes` / `nodeCount` / `skins` / `animations` /
`bounds.world{min,max,size,center,radius}` / `bounds.accessorUnion` / `boundsDeviationFactor` /
`upAxis{guess,confidence}` / `transformHealth{mirrored,nonUniform,singular}` / `generator` / `contentHash`。
> **2026-09-20 核实**：清单里有两项与实现不符，均已按实情标注——① 末项 `contentHash` **未实现**（`grep contentHash src/` 无命中），与 §4 风险表里"重复资产提示"同源、目前**未排期**；② `textureBytes`（贴图字节汇总）**在 `inspect()` 里不存在**：贴图字节只在 `report.images[].bytes` 上逐张给出，没有汇总字段，TASK-020 复核时确认。其余字段均已落地。

**新增规则（续 001 文档的 BR 编号）**

| 编号 | 规则 | 优先级 |
|---|---|---|
| BR-013 | IVE 源为 Z-up，转换必须施加 `-90° 绕 X`（`(x,y,z)→(x,z,-y)`）转到 glTF 的 Y-up；与 FBX2glTF 使用的旋转方向一致 | **已落地** |
| BR-014 | 转换后默认把世界包围盒 `min.y` 抬到 0（贴地）、X/Z 中心归零；可用 `ground:false` / `centerXZ:false` 关闭 | **已落地** |
| BR-015 | 轴转换与归心在**节点线性部分全为单位阵**时直接烘焙进顶点（使 accessor min/max 与真实盒一致）；否则退化为插入转换根节点，不得静默产生错误结果 | **已落地** |
| BR-016 | 中间产物的 `matrix` 字段判定以"字段存在"为准，不得依赖 `hasMatrix`（详见 001 文档同条目） | **已落地** |
| BR-017 | 体检报告必须同时给出"世界盒"和"accessor 并集盒"，偏差 ≥10× 时告警 | **已落地**（2026-09-20 核实：实现编号在 `docs/001-code-design.md` 里是 **BR-018**——两份文档的 BR-017/018 历史撞号，本表保留原编号并加此注，不再改动历史行） |

## 5. 里程碑与验收标准

### M1 — 看得见（只读体检 + 预览层方向/中心/缩放，不落盘）
交付：`src/inspect.js`、`src/transform.js::worldBounds`、UI 报告面板 + 实时控件。
**退出标准**：
1. `node -e "inspect('o-model/运输车.glb')"` 输出 `bounds.world ≈ 2.59×4.10×5.98`，`boundsDeviationFactor > 1000`，并列出荒谬的 `accessorUnion`。
2. 样例集 GLB 体检全跑通（0 崩溃），单文件 ≤ 2s（以 M1A2 174,937 顶点为上限样本）。样本数为实测 **21 个**（`o-model/*.glb` 18 + `model/*.glb` 3；此前写的 24 是估计值）。
3. `triangles` 与 `Σ(indices.count)/3` 全等；`vertexReuseRatio` 对 person 参考件 = 0.61。
4. 预览拖方向/缩放，人物与车辆同框可见，日志记录最终 `modelMatrix`。

### M2 — 转得对（IVE 链路 D1/D2 + 变换烘焙落盘）
**退出标准**：
1. `蹲姿` 转换产物世界盒轴位与参考件一致：X=0.538、**Y=高度**、**Z=前后深 1.056**（D1 关闭）。
2. 站立/蹲姿产物 `min.y ≈ 0`（|min.y| < 0.05）且 `|center.x|`、`|center.z|` < 0.05（D2 关闭）。
3. 转换产物 `accessorUnion` 与 `world` 偏差 < 1%（BR-015 的烘焙路径生效）。
4. 顶点数 ≤ 参考件 × 1.2（D3：person 目标 ≤ 13,800）；贴图与面数不回退（18,924 面、3 张贴图）。
5. `node --test test/ive.test.js` 全绿，且新增断言覆盖 1–4。

**当前状态（本轮结束时）**：1 ✅ 三轴与参考件完全一致；2 ✅ `min.y = 0`、中心 `(0, ·, 0)`；
3 ✅ `bake` 模式下二者相等（含旋转的文件走 `root` 模式仍会偏，属预期退化，需 M1 的世界盒上报兜住）；

**M2 退出标准已全部满足。**

1. `M1A2`、`运输车` 修复后 sampler 不再出现 `REPEAT + mipmap` 与 NPOT 组合（脚本可断言）。
